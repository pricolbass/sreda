# 01: Первый администратор входит в кабинет по HTTPS

**What to build:** владелец разворачивает Среду на подготовленной маме, вручную создаёт первого администратора и входит в сохраняющий данные веб-кабинет по HTTPS. Это минимальный работающий путь от установки до авторизованного кабинета, на котором строятся последующие сценарии.

**Blocked by:** None (can start immediately).

Status: ready-for-human

- [x] Выбраны и задокументированы минимальный серверный состав, хранилище, порядок запуска и разделение необходимых прав. Ещё не утверждённые предложения исходной спецификации не выдаются за ранее принятые решения.
- [ ] Описаны необходимые параметры мамы и общей доменной зоны; подготовлены wildcard DNS и действующий wildcard-сертификат с проверяемым способом продления. Внешний HTTPS обслуживает Caddy.
- [x] Администратор создаётся вручную на маме; публичной первичной регистрации и установочной ссылки нет.
- [x] Администратор входит по логину и паролю, видит кабинет и может выйти. Неавторизованный запрос не получает доступ к управлению.
- [x] Пароли не хранятся открытым текстом; сессия проверяется сервером, а выход прекращает её использование.
- [x] Учётная запись и необходимые настройки сохраняются после перезапуска серверной части.
- [ ] Кабинет проверен из внешней сети с действительным сертификатом. Внешнего HTTP-входа и перенаправления с HTTP нет.
- [x] Есть воспроизводимая проверка ручного создания администратора, входа, выхода, отказа в неавторизованном доступе и сохранения данных.


## Comments

### 19 октября 2026 — локальная реализация

По прямому указанию пользователя выполнено только локально и на Go.
Добавлены Go CLI/HTTP-кабинет, SQLite, bcrypt, серверные сессии, CSRF,
конфигурации Caddy и systemd. Согласованные границы тестов — CLI и HTTP
с настоящим хранилищем, включая перезапуск.

Локальная цепочка Caddy → Unix-сокет → Go проверена с доверенным для тестового
клиента локальным CA: вход, кабинет, выход и отказ при повторном использовании
отозванной cookie. Системное хранилище доверия не изменялось.

`ready-for-human` относится к оставшейся внешней приёмке: настоящая мама,
wildcard DNS, production-сертификат, автоматическое продление и проверка
из внешней сети. Эти пункты не объявлены выполненными.

### Результаты проверок

- Go 1.27.2: `go vet ./...`, `go test -race ./...` — успешно.
- Сборка `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build` — успешно;
  получен статически связанный ELF-бинарник.
- Caddy 2.11.7: локальный Caddyfile валиден; HTTPS-сценарий выполнен
  с проверкой CA и hostname, без отключения проверки сертификата.
- Production Caddyfile преобразован в JSON: слушатель `:443`, automatic HTTPS
  выключен, admin API — Unix-сокет. Это проверка конфигурации, не внешней сети.
- Ревью Standards: 0 замечаний. Ревью Spec: 0 замечаний в локальном объёме.
- Таймаут HTTP-клиента процессного теста увеличен до 15 секунд для накладных
  расходов race detector при bcrypt; повторный полный набор прошёл.
