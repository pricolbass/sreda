# 09: Пользователь переподключает существующую машину

**What to build:** после переустановки агента или утраты ключей пользователь выбирает существующую машину и получает новый одноразовый код. Новый агент занимает место прежнего, сохраняя публикации и поддомены, а старые учётные данные подключения перестают действовать.

**Blocked by:** 08 — Администратор закрывает доступ пользователя.

Status: resolved

- [x] Владелец запускает переподключение своей машины из кабинета; новая запись машины и новые поддомены не создаются.
- [x] Новые учётные данные заменяют прежние с подтверждённым отзывом старых. Ошибка отзыва, таймаут или отсутствие подтверждения не обозначаются как успешная замена.
- [x] Старый агент не может восстановить подключение, получать трафик публикаций или изменять состояние машины после замены.
- [x] Новый агент обслуживает прежние включённые публикации; сохранённые настройки и поддомены не теряются.
- [x] Код имеет определённый срок действия и используется один раз. Повторное, конкурентное и просроченное использование отвергается.
- [x] Переподключение не обходит блокировку пользователя и не включает намеренно отключённое подключение или публикацию.
- [x] Проверены успешная замена, ошибка отзыва, попытки старого агента, гонка с блокировкой и сохранение намеренно отключённых ресурсов.


## Answer

Реализовано локально в отдельном `internal/reconnection` контроллере: durable
намерение замены → отзыв старой авторизации → закрытие шлюзовых потоков и
сброс cached endpoints → проверенная очистка peer/прежних операций → новый
15-минутный код. Машина, адрес, режим, публикации и поддомены сохраняются.
Неудача не выдаёт код и сохраняет состояние для повтора после перезапуска.

Отдельный безопасный snapshot версии подключения и владельца атомарно
проверяется при ACK, выдаче control и записи контакта. Намеренно выключенная
машина принимает новые credentials без ApplyPeer и возвращает только метаданные
с пустыми routes. Потерянный ответ восстанавливается с текущими bearer+public
key через отдельный endpoint метаданных, без включения и без heartbeat.

HTTP/SQLite проверки: успешная замена и новый retained map; выключенные ресурсы;
ручной WireGuard с прежним адресом; отказ Remove и повтор после App reopen;
живой прежний Apply и поздний результат; stale authenticated control snapshot;
гонка block→unblock; конкурентное/повторное использование кода; реальный HTTPS
со старым cached proxy token; неподтверждённое закрытие downstream; потерянный
ответ выключенному агенту через реальный `agent.Enroll` и локальный TLS.
Первый HTTP-тест был красным 404; отдельные красные тесты выявили включение
выключенной машины/смену IP, отсутствие manual ready и потерю ответа off-agent.

[Инструкция](../../../docs/reconnection.md). Реальная смена WireGuard peer в
Debian LXC не проверялась по согласованному ограничению «Только локально».
