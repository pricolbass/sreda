# 04: Пользователь публикует локальное приложение по HTTPS

**What to build:** пользователь выбирает подключённую машину, указывает адрес и порт своего приложения и свободный поддомен. Среда создаёт внешний HTTPS-адрес и доставляет запросы через маму и агент к указанному приложению, включая loopback, без ручной настройки мамы для каждой публикации.

**Blocked by:** 03 — Пользователь подключает Debian LXC через агент.

Status: ready-for-agent

- [ ] Работает полный путь интернет → Caddy на маме → WireGuard → агент в LXC → явно заданный адрес и порт приложения.
- [ ] Произвольные тестовые веб-приложение и веб-API публикуются без интеграции с конкретным продуктом. Автоматический поиск приложений не требуется.
- [ ] Два приложения одной машины публикуются через одно существующее подключение, без повторной установки агента или выдачи кода.
- [ ] Поддомен проверяется и закрепляется за публикацией; конкурентный выбор одного имени не создаёт конфликтующих маршрутов. Собственные домены в этот сценарий не входят.
- [ ] Пользователь может публиковать только на своей машине. Подмена идентификатора машины или публикации не даёт доступа к чужим ресурсам.
- [ ] Агент принимает трафик только для зарегистрированных включённых публикаций своей машины и только к закреплённому адресу и порту. Неизвестная, чужая или неактивная публикация, соседний незарегистрированный порт и подмена цели отвергаются.
- [ ] В кабинете видны «Настраивается», «Настроена» и «Ошибка» с причиной. «Настроена» появляется после подтверждения применения настроек и не означает проверку здоровья приложения.
- [ ] Частичная ошибка настройки не выдаётся за успешную публикацию и не повреждает другие публикации; повторная попытка не создаёт дубликатов.
- [ ] Публикация открывается из внешней сети с действительным сертификатом только по HTTPS. Общие DNS и сертификат переиспользуются.
- [ ] Проверки охватывают реальный loopback-сервис, повторное использование подключения, коллизию имени, недопустимые цели и попытки доступа другого владельца.
