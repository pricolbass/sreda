# 08: Администратор закрывает доступ пользователя

**What to build:** администратор видит ресурсы всех пользователей и их владельцев, может отключить любую публикацию и заблокировать пользователя. Среда отличает намерение закрыть доступ от подтверждённого исполнения, сохраняя настройки и поддомены. Разблокировка разрешает новый вход, но ресурсы включаются только явно.

**Blocked by:** 02 — Администратор приглашает пользователя; 05 — Пользователь отключает и повторно включает публикацию; 07 — Пользователь публикует приложение через ручной WireGuard-конфиг.

Status: resolved

- [x] Администратор видит владельцев, настройки и состояние ресурсов и может отключить чужую публикацию. Эти полномочия не дают доступа к содержимому приложений или произвольному редактированию чужих ресурсов.
- [x] Блокировка запрещает новый вход, отзывает активные пользовательские сессии, отключает все публикации и WireGuard-подключения пользователя в обоих режимах.
- [x] Закрываются новые и уже установленные соединения. Старые учётные данные, ранее выданные коды и повторные команды не позволяют обойти блокировку.
- [x] Пока результат не подтверждён по всем частям операции, показано «Отключение выполняется» либо конкретная ошибка. «Доступ закрыт» недопустимо при неподтверждённом отзыве сессий, удалении маршрута или отключении peer.
- [x] Проверены ошибка удаления маршрута, ошибка удаления peer, таймаут и недоступность агента. Шлюз выполняет доступные шаги закрытия, а незавершённая операция может быть продолжена без ложного успеха.
- [x] Намерение блокировки и ход её исполнения сохраняются; устаревшее включение не отменяет блокировку.
- [x] Разблокировка позволяет войти заново, сохраняет отзыв старых сессий и оставляет подключения и публикации выключенными. В кабинете доступны явные действия для возвращения подключения и последующего включения публикаций.
- [x] Настройки и поддомены сохраняются. Блокировка не выполняет окончательное удаление пользователя или его ресурсов.
- [x] Проверки охватывают оба способа подключения, несколько машин и публикаций одного пользователя и сохранение доступа другого пользователя.



## Answer

Локальная реализация завершена. Тонкие HTTP-адаптеры обращаются к
`internal/access.Controller`, который координирует identity, publication и
machine через интерфейсы потребителя. SQL и атомарные снимки остаются в
закрытых SQLite-адаптерах соответствующих модулей.

Блокировка атомарно отзывает сессии, увеличивает версию доступа владельца,
закрывает все публикации и подключения обоих режимов, отзывает коды и
сохраняет ошибки неподтверждённой очистки. Действующие аренды настройки не
считаются удалёнными peers. Старые результаты Apply не могут включить ресурс;
ACK, контакт и карта маршрутов повторно проверяют версию владельца.
Разблокировка допускается после подтверждения и оставляет ресурсы выключенными.
Машина имеет отдельные желаемое состояние и подтверждённое применение.
