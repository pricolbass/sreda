# 07: Пользователь публикует приложение через ручной WireGuard-конфиг

**What to build:** пользователь подключает машину без агента с помощью готового WireGuard-конфига, самостоятельно делает приложение доступным через туннель и получает HTTPS-публикацию из кабинета. «Настрою сам» показывает расширенные параметры того же подключения.

**Blocked by:** 04 — Пользователь публикует локальное приложение по HTTPS.

- [x] Пользователь получает готовый конфиг и соответствующие расширенные параметры. Они относятся к одной записи машины и одному подключению.

- [x] Несколько публикаций переиспользуют подключение. Поддомен, владение и подтверждение применения настроек соблюдают общие правила публикаций.

## Answer

Локальная реализация завершена. Режим подключения сохраняется в записи машины
и в незавершённой операции через ссылку на неё. Браузер создаёт X25519 и
скачивает готовый конфиг; private key не отправляется серверу и не сохраняется
в browser storage. Для браузера без X25519 есть локальная генерация через wg
и форма только публичного ключа с явно обозначенным шаблоном.

Ручной режим не получает proxy token и не может использовать heartbeat агента.
Публикации доставляются двумя адаптерами через общий интерфейс транспорта;
ручной адаптер разрешает только назначенный этой машине IP WireGuard и порт.
Несколько публикаций используют одно подключение. Отключение закрывает общий
механизм потоков; повторное включение ручной публикации не ждёт ACK агента.

Связь определяется проверенным WireGuard-handshake helper, с кешем наблюдения
не дольше 30 секунд и отдельной свежестью handshake 180 секунд. Ошибка
наблюдения не превращает сохранённое время в подтверждённую связь. Все эти
решения приняты при реализации, а не приписаны прежним согласованиям.

Документация: [manual-wireguard.md](../../../docs/manual-wireguard.md).
