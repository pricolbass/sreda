# 07: Пользователь публикует приложение через ручной WireGuard-конфиг

**What to build:** пользователь подключает машину без агента с помощью готового WireGuard-конфига, самостоятельно делает приложение доступным через туннель и получает HTTPS-публикацию из кабинета. «Настрою сам» показывает расширенные параметры того же подключения.

**Blocked by:** 04 — Пользователь публикует локальное приложение по HTTPS.

Status: ready-for-agent

- [ ] Определён и реализован процесс подготовки клиентских ключей и готового конфига. Выбор способа генерации и обращения с private key явно задокументирован, а не выдан за уже согласованный.
- [ ] Пользователь получает готовый конфиг и соответствующие расширенные параметры. Они относятся к одной записи машины и одному подключению.
- [ ] Приложение, доступность которого через туннель обеспечил пользователь, открывается по выбранному HTTPS-поддомену. Автоматическая доставка к loopback без агента не обещается.
- [ ] Несколько публикаций переиспользуют подключение. Поддомен, владение и подтверждение применения настроек соблюдают общие правила публикаций.
- [ ] Состояние связи и последний контакт отображаются на основании определённого наблюдаемого сигнала; они не обозначают здоровье приложения.
- [ ] Мама запрещает приватную связь между клиентскими машинами и доступ к своим внутренним административным интерфейсам, включая попытки с изменённым клиентским конфигом.
- [ ] Проверены подключения без агента между собой и с агентом, в обоих направлениях. Для проверки изоляции используются отдельные тестовые владельцы и несколько машин одного владельца.
- [ ] Существующие операции жизненного цикла применяются к этому способу подключения; последующие задачи на отключение, удаление и блокировку должны проверять оба способа.
