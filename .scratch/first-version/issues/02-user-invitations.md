# 02: Администратор приглашает пользователя

**What to build:** администратор создаёт в кабинете приглашение и лично передаёт ссылку человеку. Человек задаёт логин и пароль и получает собственный кабинет. Открытой регистрации и отправки почты нет.

**Blocked by:** 01 — Первый администратор входит в кабинет по HTTPS.

Status: ready-for-agent

- [ ] Администратор может создать приглашение, получить ссылку, увидеть срок действия и отменить неиспользованное приглашение.
- [ ] Срок действия и поведение незавершённой регистрации определены и отражены в интерфейсе.
- [ ] Принятие действующего приглашения создаёт обычного пользователя с выбранными им логином и паролем. Коллизия логина обрабатывается без повреждения приглашения или чужого аккаунта.
- [ ] Просроченная, отменённая и уже использованная ссылка отвергается. Одновременное принятие одной ссылки не создаёт несколько аккаунтов.
- [ ] Пользователь может войти и выйти; ему недоступны административные операции, в том числе при прямом обращении к серверу.
- [ ] Разделение пользователей проверяется на доступных к этому моменту данных и операциях; последующие задачи обязаны проверять владение своими новыми ресурсами.
- [ ] Сценарий проверен с тестовыми аккаунтами. Приглашение реальных пользователей допускается после отдельной обязательной проверки закрытия доступа и изоляции в задаче 13.
