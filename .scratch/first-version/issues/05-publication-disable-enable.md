# 05: Пользователь отключает и повторно включает публикацию

**What to build:** пользователь закрывает внешний доступ к публикации, сохраняя её поддомен и настройки, а затем явно включает её по прежнему адресу. Приложение на машине продолжает работать независимо от публикации.

**Blocked by:** 04 — Пользователь публикует локальное приложение по HTTPS.

Status: resolved

- [x] Отключение и включение доступны владельцу в кабинете и проверяют полномочия на сервере.
- [x] Во время отключения показывается «Отключается»; «Отключена» означает подтверждённое закрытие внешнего доступа. Ошибка и отсутствие подтверждения отображаются явно.
- [x] Отключение закрывает новые и уже установленные соединения публикации; закрытие контролируется на маме и не зависит только от ответа агента.
- [x] Недоступность агента не мешает закрыть доступ через шлюз; ошибка изменения маршрута или таймаут не считаются успехом.
- [x] Поддомен и настройки остаются закреплены; локальное приложение не останавливается. Явное включение возвращает прежний внешний адрес без повторного подключения машины.
- [x] Повторные запросы и устаревшие команды не отменяют более позднее намеренное отключение. Состояние операции сохраняется для дальнейшего восстановления после перезапуска.
- [x] Проверены отключение при активном соединении, недоступном агенте и ошибке применения, повторное включение и сохранение работы другой публикации.



## Answer

20 октября 2026: завершена локальная реализация. HTTP вызывает
`publication.Module.SetEnabled`; SQL и атомарные версии находятся в
`access_store.go`, а закрытие активных потоков — в адаптере пересылки.
Отключение сначала сохраняет намерение, запрещает допуск, закрывает HTTP и
WebSocket и только после подтверждения показывает «Отключена». Таймаут
остаётся ошибкой; повторная очистка продолжает действие. Ожидание одного
потока не удерживает общий замок и не задерживает чужую публикацию.

Через согласованные HTTP-интерфейсы проверены версия команды, повтор,
запрет старого включения/ACK, владельцы, право администратора только на
отключение чужого, реальные поток и WebSocket, живое второе приложение,
недоступный/неподтверждённый downstream и сохранение SQLite после перезапуска.
Преднамеренный сбой закрытия воспроизвёл задержку другой публикации; после
исправления тот же сценарий прошёл. Стенд заменяет только WireGuard-соединение
локальным сетевым адаптером, не подтверждает фактическую изоляцию Linux.
