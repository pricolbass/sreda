# 06: Пользователь удаляет публикацию и освобождает машину

**What to build:** пользователь окончательно удаляет публикацию с подтверждением потери поддомена. После удаления всех связанных публикаций он может удалить машину; кабинет объясняет, какие публикации пока препятствуют этому.

**Blocked by:** 05 — Пользователь отключает и повторно включает публикацию.

Status: resolved

- [x] Удаление требует явного подтверждения, что имя будет освобождено и может быть занято другим пользователем.
- [x] Сначала подтверждается очистка доступа и старого маршрута, затем освобождается поддомен. Ошибка или таймаут оставляют имя зарезервированным и показывают незавершённое удаление.
- [x] Удалённая публикация больше не принимается агентом; повторные и устаревшие команды не восстанавливают её маршрут.
- [x] Другой пользователь может занять освобождённое имя без попадания запросов к прежнему приложению.
- [x] Общие wildcard DNS и сертификат сохраняются, остальные публикации работают.
- [x] Машину нельзя удалить, пока существуют связанные публикации, включая отключённые. Кабинет перечисляет препятствия; каскадного удаления нет.
- [x] После удаления последней публикации машину можно удалить с прекращением её подключения и отзывом учётных данных; незавершённая очистка не отображается как успешное удаление.
- [x] Владение проверяется сервером. Проверены ошибки очистки, повторные запросы и конкурентные создание публикации, удаление машины и повторное занятие поддомена.


## Answer

Локальная реализация завершена. Удаление публикации проверяет владельца,
версию и введённый поддомен. Намерение, закрытый доступ и версия удаления
сохраняются до закрытия потоков. В режиме агента имя освобождается после
ACK карты без старого ID; ручной режим завершает удаление после подтверждения
закрытия шлюза. Ошибка или таймаут сохраняют резервирование имени. Постоянные
записи удалённых ID исключают их повторное использование и влияние старой
команды на нового владельца имени.

Машина удаляется только без любых публикаций; препятствующие имена показаны
в ответе кабинета. Код и учётные данные отзываются до сетевой очистки.
Операции подключения и удаления имеют сохранённые leases; позднее применение
peer не может успешно включить удаляемую машину. При незавершённой очистке
запись и адрес сохраняются, служба согласования повторяет попытку. Числовые
ID машин учитывают также удалённые записи и не переиспользуются в обоих режимах.

Документация: [deletion.md](../../../docs/deletion.md).
