# 11: Пользователь восстанавливает пароль через администратора

**What to build:** администратор создаёт в кабинете одноразовую ссылку восстановления и лично передаёт её пользователю. Пользователь самостоятельно задаёт новый пароль. Аварийное восстановление администратора выполняется вручную на маме.

**Blocked by:** 02 — Администратор приглашает пользователя.

Status: resolved

- [x] Администратор выбирает пользователя, создаёт ссылку и видит срок её действия. Отправка почты не требуется.
- [x] По действующей ссылке пользователь самостоятельно задаёт новый пароль; администратор не получает этот пароль.
- [x] Определены срок действия ссылки, поведение при выдаче следующей ссылки и политика существующих сессий после смены пароля; поведение явно проверено.
- [x] Использованная и просроченная ссылка отвергается. Конкурентное применение одной ссылки не выполняет несколько смен пароля.
- [x] После восстановления новый пароль работает, прежний не работает. Восстановление пароля само по себе не меняет права пользователя или состояние его ресурсов.
- [x] Обычный пользователь не может выдавать ссылки восстановления другим людям или подменить целевого пользователя.
- [x] Описан и проверен ручной способ аварийного восстановления администратора на маме без публичного механизма восстановления администратора.



## Comments

### 20 октября 2026 — локальная реализация

Администратор выбирает обычного пользователя и получает одноразовую ссылку
на 1 час. Точная дата в UTC показана и администратору, и пользователю;
следующая выдача немедленно заменяет прежнюю ссылку. Ошибка ввода и
открытие страницы ссылку не используют. После успешной смены отзываются
все сессии аккаунта, права и состояние ресурсов не меняются.

Локальные HTTP-проверки с настоящей SQLite покрывают новый/старый пароль,
две ранее действовавшие сессии, подмену user_id, отказ обычному пользователю
в выдаче ссылок, запрет выдачи для администратора, заменённую/использованную/
просроченную ссылку, невалидный пароль и конкурентное применение ссылки
двумя экземплярами приложения. SQL используется только для подготовки
просроченного fixture; результат проверяется через HTTP.

CLI `reset-admin` проверен через CLI и HTTP: меняет пароль существующего
администратора, отзывает его сессию, не печатает пароль и не меняет обычный
аккаунт. Публичного восстановления администратора нет. Вход перед записью
сессии перепроверяет актуальный хеш, чтобы вход со старым паролем, начатый
до восстановления, не создал новую сессию после завершения восстановления.

TDD: восстановление через кабинет сначала падало с 404, затем прошло;
ручной сброс сначала отвергался как неизвестная команда, затем прошёл.
Инструкция: [восстановление пароля](../../../docs/password-recovery.md).
Вся работа выполнена локально; ссылки людям не передавались.

Проверки: `go vet ./...`, `go test ./...` (локальные Unix-сокеты разрешены),
все пять новых сценариев с `go test -race` — успешно. После выделения общей
проверки пароля повторно прошли сценарии регистрации и замены ссылки.
