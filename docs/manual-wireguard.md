# Ручное подключение WireGuard

Решение реализации задачи 07 от 20 октября 2026 года. Пользователь выбрал
только локальную реализацию; развёртывание в Debian LXC и внешняя приёмка
в этой работе не выполнялись.

## Получить готовый конфиг

В «Машинах» выберите «Ручной WireGuard». Запись принадлежит текущему
пользователю; способ подключения фиксируется до использования кода.
Нажмите «Создать и скачать конфиг». Браузер генерирует X25519-ключи,
передаёт кабинету только публичный ключ и сохраняет готовый файл локально.
Код действует 15 минут и используется один раз. После потери ответа можно
повторить действие на той же странице: сохранённый в её памяти ключ сверяется
с публичными параметрами уже зарегистрированной машины.

Private key существует только в памяти страницы и скачанном конфиге.
Он не передаётся серверу, не попадает в базу, журналы, URL или browser storage.
После закрытия страницы сервер не сможет повторить скачивание private key.
Сохраните файл; при утрате ключа используется переподключение прежней машины,
а не создание новой записи ради сохранённых публикаций.

Генерация требует HTTPS и поддержки X25519 WebCrypto. Выполняется проверка
generateKey и экспорта; отсутствие поддержки оставляет рабочую форму для
публичного ключа. Локальная альтернатива в Debian с `wireguard-tools`:

```sh
umask 077
wg genkey > sreda-private.key
wg pubkey < sreda-private.key > sreda-public.key
```

В кабинет вставляется только `sreda-public.key`. Затем скачивается явно
обозначенный шаблон; замените `PRIVATE_KEY_FROM_LOCAL_FILE` содержимым
`sreda-private.key` в локальном редакторе. Шаблон без этого изменения не
обозначается готовым конфигом. Не вводите private key в форму кабинета.

Внутри подготовленного Debian LXC конфиг устанавливается оператором машины:

```sh
sudo install -m 0600 wg-sreda.conf /etc/wireguard/wg-sreda.conf
sudo systemctl enable --now wg-quick@wg-sreda
```

Нужны доступ к WireGuard ядра Proxmox, разрешённые полномочия настройки сети
внутри LXC и systemd; требования подготовки хоста описаны в [agent.md](agent.md).
Само скачивание файла не подтверждает поддерживаемость окружения.

## Параметры и публикации

«Настрою сам» показывает публичный ключ, назначенный /32, endpoint и ключ
мамы, `AllowedIPs=10.203.0.1/32`, `PersistentKeepalive=25` для той же записи
машины. Второй peer не создаётся. Клиентский конфиг не содержит default route,
DNS-перенастройки или shell hooks. На маме остаётся подготовленный оператором
маршрут сети через интерфейс с адресом `10.203.0.1/24`.

Приложение должно слушать назначенный машине IP WireGuard и выбранный порт,
например `10.203.0.2:8080`. Loopback, LAN и IP соседнего peer отвергаются.
Доставка: HTTPS Caddy → шлюз Среды → точный IP:порт машины по WireGuard.
Авторизация посетителей остаётся ответственностью приложения. Несколько
публикаций используют один peer; агент и его внутренний proxy token не нужны.
Отключение и повторное включение публикации проходят через общий механизм
закрытия активных соединений; включение ручной публикации не ждёт ACK агента.

## Наблюдение связи и изоляция

Ручное подключение не принимает heartbeat агента даже с правильным bearer.
Контакт наблюдает привилегированный helper через `wg show ... latest-handshakes`
только для проверенного активного ключа и его точного адреса. Ответы агента,
браузера или приложения не подменяют этот сигнал.

Результат наблюдения кешируется отдельно для каждой машины максимум на 30 секунд.
Ошибка нового наблюдения запрещает считать старое время подтверждённой связью.
После перезапуска требуется новое наблюдение, сохранённой даты недостаточно.
«На связи» означает подтверждённый handshake младше 180 секунд при включённом
подключении. Такой срок учитывает обновление handshake примерно раз в две
минуты; keepalive 25 секунд не означает новый handshake каждые 25 секунд.
Это не проверка исправности приложения. Статус «Настроена» также означает
применённые настройки публикации, а не здоровье сервиса.

Общий helper применяет одинаковую изоляцию обоих режимов: запрет forwarding
между любыми клиентами и новых обращений через туннель к маме, уникальный
серверный AllowedIPs /32, запрет IPv6 в неподдерживаемом туннеле. Изменение
клиентом своего конфига эти правила не отменяет. Управление helper остаётся
только через ограниченный Unix-сокет; наблюдение не выдаёт чужие ключи или
необработанный вывод системной программы.

## Проверки и оставшаяся приёмка

Локальные HTTP-проверки используют настоящую SQLite, общий механизм публикаций
и локальный HTTPS с реальным приложением. Проверены границы цели, отсутствие
proxy token у ручного подключения, запрет heartbeat, состояние по handshake,
ошибка наблюдения после перезапуска, повторное использование подключения,
отключение и явное включение. HTML-проверка подтверждает отдельный CSP nonce
и доступность формы локальной генерации.

Скрипт страницы отдельно выполнен в Node WebCrypto с моделью DOM: публичный
ключ, заново вычисленный из private key готового конфига, совпал с отправленным
серверу ключом; запрос содержал только code, credential и public_key. Это
проверка криптографического преобразования, а не совместимости всех браузеров.

Не проверены реальный WireGuard в Debian LXC, запреты между враждебными peers
обоих режимов и владельцев, перезапуск сетевых компонентов, браузерный импорт
конфига в WireGuard и внешний wildcard HTTPS. До приглашения пользователей
они остаются обязательной приёмкой задачи 13. Удаление, блокировка и
переподключение проверяются также в соответствующих следующих задачах.
