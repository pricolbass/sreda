# Окончательное удаление ресурсов

Отключение сохраняет имя и настройки. Удаление публикации окончательно
освобождает имя, которое может занять другой человек. В карточке публикации
нужно ввести её поддомен в поле подтверждения потери имени. Сервер проверяет
владельца, подтверждение и текущую версию записи.

Удаление сначала сохраняет намерение и запрещает новые внешние запросы.
Шлюз закрывает активные HTTP/WebSocket-соединения этой публикации. Для
агентского подключения из следующей карты маршрутов полностью исключается
ID публикации. Имя освобождается только после подтверждённого закрытия
соединений шлюза и подтверждения агентом новой версии карты. Другие
публикации и общие DNS/сертификат не изменяются.

Если агент недоступен, карточка остаётся в состоянии «Удаляется» с причиной,
а имя остаётся зарезервированным. Таймаут закрытия соединений также сохраняет
запись. Повторить удаление можно в той же карточке; повтор не создаёт новую
публикацию и не обходит проверку очистки. После подтверждения карта удаляет
старый ID; постоянный tombstone не позволяет повторным командам восстановить
его или затронуть новую публикацию с тем же именем.

Машину можно удалить только после удаления всех её публикаций. Отключённые
и ожидающие удаления публикации тоже препятствуют удалению. Кабинет
перечисляет поддомены; каскадного удаления публикаций нет. При удалении
машины код и управляющие учётные данные отзываются сразу, новые подключения
и публикации запрещаются. Запись и её адрес сохраняются до подтверждённого
удаления peer и очистки незавершённой регистрации/изменения подключения.
Если операция ещё выполняется, показывается «Удаляется». При ошибке
сетевого helper отображается причина и доступно повторение.

Служба согласования повторяет незавершённую очистку машин. Фоновые операции
имеют долговечный lease: поздний ответ старого подключения не может
включить удаляемую машину. SQLite-транзакции фиксируют намерение и проверяют
препятствия, затем завершаются до вызовов сетевого helper. Окончательное
удаление повторно проверяет отсутствие публикаций и выполняемых операций.
Числовые ID машин и случайные ID публикаций не переиспользуются.

## Локальное подтверждение

HTTP-проверки с настоящей SQLite покрывают подтверждение потери имени,
удаление после agent ACK, запрет старого ID в настоящем proxy агента,
переход имени другому владельцу и доставку запросов только новому приложению.
Проверена сохранность соседней публикации, блокировка удаления машины
отключённой публикацией, отказ сетевой очистки с немедленным отзывом
учётной записи агента, конкурентные создание публикации/удаление машины и
удаление во время регистрации другим экземпляром кабинета. Тест с
настоящим HTTP-потоком и намеренно зависшим downstream доказывает, что одного
agent ACK недостаточно для освобождения имени после таймаута шлюза.

Kernel WireGuard в этих проверках заменён внешним адаптером. Действительная
очистка сетевых правил, два Debian LXC и внешняя сеть требуют отдельного
стенда; они не заявляются проверенными по указанию «Только локально».
