# Локальная приёмка и оставшиеся условия выпуска

20 октября 2026 года. Выполнение ограничено указанием пользователя
«Только локально». Реализованы функциональные задачи 01–12.
**Готовность приглашать реальных пользователей не подтверждена:**
обязательная внешняя часть задачи 13 и нагрузочная часть 14 не выполнены.

## Локальная среда

macOS 15.8.1 (24H32), Darwin arm64, Go 1.27.2, Caddy 2.11.7.
Настоящие SQLite, HTTP/HTTPS, WebSocket, Caddy и proxy агента.
Проверяется цепочка локального CA и имя HTTPS-хоста; проверка сертификата
не отключается. Только границы kernel/WireGuard и назначенных туннельных
адресов заменены управляемым внешним адаптером. Это не Debian LXC.

Воспроизведение из корня репозитория с установленными Go и Caddy:

```sh
SREDA_TEST_CADDY=/абсолютный/путь/caddy go test -race ./internal/cabinet \
  -run '^TestLocalReadinessAcrossOwnersAndRestartThroughCaddy$' -count=1
SREDA_TEST_CADDY=/абсолютный/путь/caddy make check test
```

Без `SREDA_TEST_CADDY` сценарий с Caddy пропускается — это не успешная
проверка HTTPS. Нужны разрешённые временные локальные TCP/Unix-сокеты.

## Сквозной результат

`TestLocalReadinessAcrossOwnersAndRestartThroughCaddy`: **PASS**,
целевой race-прогон 20.023 s. Все формы и API проходят через настоящий
Caddy с локальным CA и Unix backend. Два приглашённых владельца создают
свои ресурсы; одна машина публикует два loopback-приложения через агент,
другая использует ручной WireGuard. Ответы содержат различные маркеры
владельца и приложения, чтобы обнаружить неправильную доставку.

Проверено последовательно:

1. Приглашение, вход, подключение и четыре HTTPS-публикации;
   запрет чтения чужих ресурсов и игнорирование поддельных заголовков маршрута.
2. Переподключение существующей машины: старый агент отвергается,
   ID и HTTPS-адреса публикаций сохранены, новая доставка работает.
3. Ошибка удаления peer при блокировке: сессия, вход, старый код и
   публикации первого владельца недоступны; показана ошибка закрытия,
   второй владелец продолжает получать своё приложение.
4. Открытие сохранённой БД новым App при том же Caddy: согласование
   продолжает блокировку без повторного POST «Заблокировать» и подтверждает
   закрытие только после успешной сетевой очистки.
5. Разблокировка не возвращает старую сессию или ресурсы. После нового
   входа отдельно включаются машина и одна публикация; вторая публикация
   и ручная машина остаются отключёнными, второй владелец сохраняет доступ.

При блокировке публичные маршруты отвечают 404; после разблокировки
намеренно отключённые маршруты — 503. В обоих случаях приложение недоступно.
Смена App здесь обозначает открытие БД заново, а не перезапуск ОС/процесса.
Настоящий дочерний процесс сервера и перезапуск Caddy проверяются отдельно
в сценариях задачи 10.

она не доказывает отсутствие внешнего listener/firewall на настоящей VDS
или правильность ещё не предоставленного публичного сертификата.

## Обязательная внешняя матрица — не выполнена

Перед запуском записать Debian, Proxmox/kernel, параметры LXC и capabilities,
версии WireGuard/nftables/iproute2/Caddy, units, права сокетов, публичный IP
и зону. Использовать минимум двух тестовых владельцев и несколько машин
каждого, с агентом и без него. Приватные ключи, токены и пароли в отчёт
не включать.

| Проба | Ожидание | Фактический результат |
| --- | --- | --- |
| Внешние DNS, wildcard SAN/цепочка, HTTPS из другой сети | Доверенный HTTPS кабинета и публикаций | Не запускалась |
| Автоматическое продление и предъявление обновлённого production-сертификата | Проверены timer, hook и новый сертификат на внешнем HTTPS | Не запускалась |
| TCP/80, публичные backend/admin-порты, обе IP-семьи при AAAA | Отказ без HTTP-ответа/редиректа; административные сокеты закрыты извне | Не запускалась |
| Все направленные пары agent→agent, agent→manual, manual→agent, manual→manual; свой и чужой владелец | Приватные соединения запрещены в обоих направлениях | Не запускалась |
| Враждебный ручной клиент: расширенные AllowedIPs/routes, соседний IP/порт, forged source, IPv6 и внутренние порты мамы | Запрет сохраняется, разрешённые HTTPS-публикации работают | Не запускалась |
| Блокировка с новыми и действующими потоками, старый WG-ключ/код/credential | Доступ отозван; ложного подтверждения нет | Не запускалась |
| Реальные ошибки nft/WG, таймаут, недоступный агент, рассогласование политики | Ошибка/ожидание до подтверждения; другой владелец работает | Не запускалась |
| Рестарты helper, WG, backend, Caddy и перезагрузка LXC, включая середину блокировки | Изоляция сохраняется; включённые ресурсы восстанавливаются, отключённые закрыты | Не запускалась |
| Целевой браузер: генерация/скачивание конфига, отсутствие private key в запросах, импорт WG, clipboard | Работают реальный handshake и HTTPS; ключ остаётся локальным | Не запускалась |

Для каждой пробы сохранить дату, точную команду/условия, ожидаемое,
фактическое, очищенный вывод и `pass`, `fail` либо `not-run`.
Пропуск обязательной строки препятствует заявлению о готовности.
Начальные команды развёртывания — в [deployment.md](deployment.md),
сетевая политика — в [network-helper.md](network-helper.md).
Вместимость 100 LXC, бюджет 2–4 ГБ и пропускная способность требуют
отдельного испытания задачи 14; успешная локальная имитация их не подтверждает.
