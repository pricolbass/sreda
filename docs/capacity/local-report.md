# Частичная локальная проверка 100 подключений и 200 публикаций

**Результат: функциональная проверка пройдена; вместимость мамы не подтверждена.**

20 октября 2026 года. Пользователь ограничил работу локальной средой.
Проверялся уже реализованный контракт HTTP/SQLite: первый запуск прошёл,
код продукта для этого сценария не менялся. Ошибку ради искусственного
«красного» теста не создавали.

## Стенд и воспроизведение

- macOS 15.8.1, build 24H32, arm64; Go 1.27.2 darwin/arm64.
- Caddy 2.11.7, отдельный локальный процесс с wildcard-сертификатом локального CA;
  клиент проверяет доверие и hostname, системное хранилище доверия не меняется.
- Настоящая SQLite и HTTP-формы/JSON API. Сетевой helper/WireGuard заменены
  только на внешней границе тестовым адаптером, учитывающим разрешённые peers.
- 100 логических подключений: по 50 на двух приглашённых владельцев,
  у каждого 40 с агентским режимом и 10 с ручным. Ключи и credentials независимы.
- 80 настоящих `agent.Proxy` работают в одном тестовом Go-процессе; это
  не 80 демонов на разных машинах. У ручных подключений нет настоящих WG-клиентов.
- 200 отдельных локальных HTTP-приложений, по два на подключение. Их ответы
  содержат owner, machine ID, номер приложения и opaque publication ID.
- Путь запросов: Caddy → Unix-сокет → кабинет → логическая WG-доставка →
  настоящий агентский прокси либо ручная цель → настоящий HTTP-сервер приложения.

Исходная интеграция: `658409d`; checkpoint теста: `314fe2d`.
Файл: `internal/cabinet/hundred_connections_test.go`.

```sh
SREDA_TEST_CADDY=/абсолютный/путь/caddy \
  go test -v ./internal/cabinet \
  -run TestFunctionalHundredConnectionsAndTwoHundredPublications -count=1

SREDA_TEST_CADDY=/абсолютный/путь/caddy \
  go test -race -v ./internal/cabinet \
  -run TestFunctionalHundredConnectionsAndTwoHundredPublications -count=1
```

Без `SREDA_TEST_CADDY` сценарий использует локальный HTTPS-сервер и явно пишет
это в журнал. Приведённые результаты получены **с настоящим Caddy**, а не
из пропущенного Caddy-сценария.

## Фактические результаты

| Проверка | Фактический результат |
| --- | --- |
| 100 записей подключены с разными ключами, credentials и адресами | PASS, внешний адаптер содержит 100 разрешённых peers |
| Две публикации используют каждое существующее подключение | PASS, всего 200 publication ID; карта каждого агента содержит две публикации |
| Доставка всех 200 HTTPS-адресов | PASS, каждый ответ точно совпал с маркером собственного приложения |
| Ручные credentials не аутентифицируют heartbeat агента | PASS, все 20 отвергнуты HTTP 401 |
| Подключение 101-й машины при полном пуле | PASS, HTTP 503 с причиной исчерпания; первые 100 peers сохранены |
| Блокировка Alice с 50 машинами/100 публикациями | PASS, 50 её peers сняты, 100 HTTPS-адресов отказали, старые credentials её агентов отвергнуты |
| Сохранение Bob | PASS, его 50 peers, 100 точных HTTPS-ответов и heartbeat 40 агентов сохранились |
| Обычный запуск | PASS, тест 1.85 с; внутреннее elapsed 1.836 с |
| Запуск с race detector | PASS, тест 17.88 с; пакет 19.362 с; внутреннее elapsed 17.854 с |

Время — длительность локального теста, включающего создание аккаунтов,
SQLite и запуск локальных серверов. Оно не является RPS, задержкой VDS,
скоростью WireGuard или результатом нагрузочного прогона.

## Что этот результат не подтверждает

Не измерялись CPU, RAM/запас памяти всего состава мамы, сетевые пределы,
устойчивая скорость, перцентили задержек, рост очередей или многочасовая
стабильность. Не запускались 100 Debian LXC и реальная сеть WireGuard;
нет свидетельства 100 одновременно действующих настоящих туннелей.
Публичный DNS/TLS, изоляция ядром, рабочие 2–4 ГБ и общий канал 1 Гбит/с
не проверены. Эти результаты не разрешают приглашение реальных пользователей.

Подготовлены [внешний протокол](protocol.md),
[предложенный профиль](profile.proposed.json) и
[незаполненный шаблон фактических результатов](external-result-template.md).
CPU, точная память и количественные ограничения должны быть утверждены
до внешнего прогона. Пока это не выполнено, задача 14 остаётся `ready-for-human`.
