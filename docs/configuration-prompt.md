# Промпт для настройки приложения

В карточке своей машины или публикации откройте «Промпт для настройки».
Добавьте описание и ссылку на документацию приложения в редактируемый текст.
Кнопка «Скопировать промпт для настройки» сообщает об успешном копировании.
Если браузер запрещает доступ к буферу, текст выделяется для ручного копирования.
Передать текст во внешнюю нейросеть пользователь может самостоятельно.
Сервер не вызывает модель, не отправляет контекст в ИИ API и не запускает
команды через агент.

Промпт машины содержит её название, способ подключения и назначенный адрес
WireGuard, если подключение уже создано. Для точного HTTPS-адреса следует
открыть промпт выбранной публикации: он дополнительно содержит её поддомен,
HTTP-адрес приложения и актуальное состояние. Каждый запрос заново читает
сохранённые параметры выбранного ресурса. Администратор не получает текст
настройки чужого ресурса через эту функцию.

Пример для агента: машина «Debian app», адрес `10.203.0.2/32`, публикация
`https://notes.example.test`, приложение `127.0.0.1:8080`. Текст объясняет,
что приложение обслуживает HTTP на этой машине, агент доставляет к нему
запросы, а HTTPS завершается на шлюзе. Он предлагает проверить внешний/base
URL, доверие proxy headers, `X-Forwarded-Proto`, redirect URL, secure cookies,
CSRF/origin и WebSocket, если приложение их использует.

Пример для ручного режима: машина «Manual app», адрес `10.203.0.2/32`,
публикация `https://docs.example.test`, приложение `10.203.0.2:9090`.
Текст явно требует самостоятельно установить конфиг и запустить WireGuard,
привязать приложение к назначенному адресу туннеля, проверить локальный
firewall и доступ от шлюза. Loopback в этом режиме недоступен шлюзу.
Один туннель подходит для нескольких публикаций; текст каждой содержит
только выбранный адрес приложения и HTTPS-адрес.

В тексте нет пароля аккаунта, private key, bearer/proxy token, кода
подключения или ссылки восстановления. Для этого машинный модуль отдаёт
отдельный DTO только с ID, названием, способом подключения и адресом.
Модуль `internal/setupprompt` получает этот DTO и параметры публикации,
проверяет принадлежность через модули ресурсов и подставляет данные в
шаблон. HTTP-обработчик отвечает за сессию, HTML и результат копирования.

Локальная проверка: HTTP с реальной SQLite для агента и ручного режима,
чужого пользователя/администратора, анонимного запроса, выбора двух разных
публикаций и отсутствия действующих секретов. Реальные браузерные разрешения
буфера обмена зависят от клиента; для отказа предусмотрено выделение текста.
