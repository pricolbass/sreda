# Трекер задач: локальный Markdown

Задачи и спецификации этого репозитория хранятся в `.scratch/`.
Все пути ниже указаны относительно корня репозитория.

## Структура

- Одна функциональность — один каталог `.scratch/<feature-slug>/`.
- Спецификация: `.scratch/<feature-slug>/spec.md`.
- Каждая задача — отдельный файл:
  `.scratch/<feature-slug>/issues/<NN>-<slug>.md`.
- Нумерация задач внутри каталога начинается с `01`.
- Статус записывается строкой `Status:` в начале файла.
  Значения определены в `docs/agents/triage-labels.md`.
- Комментарии и история обсуждения дописываются в конец файла
  под заголовком `## Comments`.

## Публикация в трекер

Когда навык требует опубликовать спецификацию или задачи,
создай соответствующие файлы по указанной структуре.
При необходимости создай каталоги.

## Чтение задачи

Когда навык требует получить задачу, прочитай файл по указанному пути.
Если передан только номер, найди его в каталоге текущей функциональности.
Если номер неоднозначен и контекст не определяет каталог, уточни задачу.

## Операции wayfinder

Для исследований через `/wayfinder` используются карта и дочерние задачи:

- Карта: `.scratch/<effort>/map.md`, с разделами Notes,
  Decisions-so-far и Fog.
- Дочерние задачи: `.scratch/<effort>/issues/<NN>-<slug>.md`,
  с нумерацией от `01` и исследуемым вопросом в тексте.
- Тип записывается строкой `Type:`:
  `research`, `prototype`, `grilling` или `task`.
- Зависимости записываются строкой `Blocked by: NN, NN`.
- Задача доступна к работе, когда все её зависимости имеют
  `Status: resolved`.
- Следующей выбирается первая по номеру доступная задача,
  которая ещё не взята в работу и не завершена.
- До начала работы запиши `Status: claimed` и сохрани файл.
- После завершения добавь результат под `## Answer`,
  запиши `Status: resolved`, затем добавь краткий вывод
  и ссылку на задачу в Decisions-so-far карты.

Значения `claimed` и `resolved` относятся к рабочему циклу wayfinder;
пять стандартных меток используются при triage.
