# Реализация задачи 01

Решения приняты для этой реализации 19 октября 2026 года. Они не выдаются
за ранее утверждённые предложения из исходной спецификации. Язык Go выбран
по прямому указанию пользователя. Внешнее развёртывание исключено из текущей
работы пользователем.

## Минимальный состав

- Один бинарный файл Go: CLI и HTTP-кабинет на `net/http`; HTML встроен в бинарник.
- SQLite через `modernc.org/sqlite`: без CGO и отдельного сервиса базы данных.
- Caddy: завершение TLS и проксирование в Unix-сокет приложения.
- systemd на маме: запуск, перезапуск, каталог состояния и разделение прав.

Очередей, контейнерной платформы, отдельного фронтенда, DNS API внутри
приложения и фоновых сетевых контроллеров на этом этапе нет. Состав не
подтверждает производительность со 100 машинами: это отдельная задача 14.

## Состояние и авторизация

В `sreda.sqlite3` хранятся логин и роль администратора, bcrypt-хеш пароля
(cost 12, случайная соль), SHA-256-хеши случайных 256-битных токенов сессий,
сроки сессий и HTTPS-адрес кабинета. Открытый пароль и исходный токен сессии
не сохраняются в базе. Сессия действует 12 часов, проверяется сервером при
каждом обращении к кабинету и удаляется при выходе. Повторный вход с той же
cookie заменяет прежнюю сессию; просроченные строки очищаются при успешном входе.

SQLite использует WAL, foreign keys, busy timeout и одну связь на процесс.
Создание схемы и сохранение origin выполняются транзакционно; `user_version=1`
позволяет последующим задачам вводить миграции. База более новой версии
отвергается. Остановка процесса не удаляет состояние.

Формы защищены случайной CSRF-cookie с префиксом `__Host-`, сравнением
токена формы и точной проверкой Origin. Обе cookie имеют Secure, HttpOnly,
SameSite=Strict, Path=/ и не имеют Domain: публикации на соседних поддоменах
не должны получать cookie кабинета. Управление доступно только на одном Host.
Выход — только POST. Ответы не кешируются; задан CSP и запрещены iframe.

Приложение доверяет `X-Forwarded-Proto` **только потому, что его единственный
слушатель — Unix-сокет с ограниченными правами**. Caddy перезаписывает этот
заголовок. Добавление TCP-слушателя потребует пересмотра границы доверия.
Запрос без TLS-признака отвергается с 403, без перенаправления.

## Права

| Компонент | Разрешено | Не требуется |
| --- | --- | --- |
| `sreda` | Своя БД и Unix-сокет | Root, TLS-ключ, DNS API, управление Caddy |
| `caddy` | TLS-ключ и подключение к сокету | Чтение БД Среды |
| Оператор / root | Установка, создание администратора от пользователя `sreda`, сертификат | Ежедневное управление через shell |

Общая группа `sreda-proxy` даёт Caddy доступ только к сокету. Каталог БД имеет
режим 0700; сертификаты принадлежат root:caddy, и `sreda` не входит в `caddy`.
Веб-маршрутов регистрации, установки и сброса пароля администратора нет.

## Следующие границы

Не реализованы приглашения, обычные пользователи, машины, публикации,
сетевое управление и блокировки. Перед допуском реальных пользователей
нужна задача 13; локальная проверка кабинета её не заменяет.

Источники реализации: [net/http](https://pkg.go.dev/net/http),
[bcrypt](https://pkg.go.dev/golang.org/x/crypto/bcrypt),
[SQLite-драйвер](https://pkg.go.dev/modernc.org/sqlite),
[отключение автоматического HTTP в Caddy](https://caddyserver.com/docs/caddyfile/options#auto-https).
