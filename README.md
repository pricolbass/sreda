# Среда

Среда — кабинет для подключения своих машин и публикации приложений по HTTPS.
Сервер написан на Go, данные сохраняются в SQLite, HTTPS обслуживает Caddy.

Локально реализованы вход и ручное восстановление администратора, приглашения
обычных пользователей, восстановление пароля, агент и ручной WireGuard,
HTTPS-публикации, отключение, включение и удаление ресурсов, блокировка
пользователя, переподключение машины, восстановление после перезапусков
и промпт настройки приложения. Это 12 функциональных задач спецификации.
Локальные проверки и оставшаяся внешняя приёмка описаны в
[отчёте](docs/local-acceptance.md) и `.scratch/first-version`.

Код разделён на модули учётных записей, машин, управления агентом и публикаций.
HTTP-обработчики разбирают запросы и отображают результаты; прикладные правила,
SQLite и сетевые операции находятся в соответствующих модулях и адаптерах.

## Локальный запуск

Нужны Go 1.27.2+ и Caddy 2.11.7+. Команды выполняются из корня репозитория.

```sh
make build # собирает sreda, sreda-agent и sreda-network
mkdir -p var/run
chmod 700 var var/run
./bin/sreda create-admin --data-dir "$PWD/var/data" \
  --origin https://localhost:8443 --login owner
```

Введите пароль дважды в терминале; ввод скрыт. Пароль — 12–72 байта,
логин — 3–64 ASCII-символа: буквы, цифры, `_`, `.` или `-`, начиная с буквы
или цифры. Логины чувствительны к регистру. Повторное создание занятого
логина не меняет его пароль. Публичного создания администратора нет.

В первом терминале:

```sh
./bin/sreda serve --data-dir "$PWD/var/data" --socket "$PWD/var/run/http.sock"
```

Во втором:

```sh
export SREDA_SOCKET="$PWD/var/run/http.sock"
export XDG_DATA_HOME="$PWD/var/caddy-data"
export XDG_CONFIG_HOME="$PWD/var/caddy-config"
caddy run --config deploy/Caddyfile.local
```

Откройте **https://localhost:8443**. Это локальный сертификат Caddy;
автоматическая установка его CA в системное хранилище отключена.
Для проверки без изменения системного доверия:

```sh
curl --cacert var/caddy-data/caddy/pki/authorities/local/root.crt \
  https://localhost:8443/login
```

Для браузера можно отдельно импортировать этот CA в доверенные сертификаты
своего тестового профиля. Не отключайте проверку сертификата для внешнего
развёртывания. Локальная конфигурация слушает только loopback; HTTP-входа
и редиректа с HTTP нет. Приложение принимает только Unix-сокет.

После остановки и повторного запуска используется тот же каталог данных.
Администратор, HTTPS-адрес кабинета и действующие сессии сохраняются.
Адрес задаётся при первом запуске; попытка незаметно заменить его при запуске
отвергается. Для другого локального адреса создайте отдельный каталог данных.

## Проверки

```sh
make check
make test
```

`make test` запускает набор с race detector через CLI и HTTP с настоящей SQLite:
аккаунты, одноразовые ссылки, права владельцев, агент, версии публикаций,
активные HTTP/WebSocket-потоки и восстановление после перезапуска. Нужны
разрешённые временные локальные TCP/Unix-сокеты.

Для проверки настоящего Caddy с локальным CA дополнительно задать путь:

```sh
SREDA_TEST_CADDY=/абсолютный/путь/caddy make test
```

Этот сценарий проверяет Caddy → Unix-сокет → Go → агент → локальное приложение.
WireGuard заменяется только на сетевом интерфейсе локального стенда. Kernel
WireGuard, Debian LXC и внешняя сеть этим прогоном не подтверждаются.

Для автоматизации CLI поддерживает `--password-stdin`. Передавайте пароль
через защищённый stdin, а не аргумент командной строки; обычная ручная
процедура использует терминал. Не сохраняйте реальные пароли в shell history.

Обычный локальный запуск выше позволяет проверить кабинет и ссылки; для
подключений и публикаций нужны подготовленные WireGuard и сетевой helper.
Без них регистрация машины возвращает явную ошибку, сохраняя код.
Реальная мама, wildcard DNS, публичный сертификат и его продление в этой
работе не настраиваются: пользователь ограничил выполнение локальной средой.
